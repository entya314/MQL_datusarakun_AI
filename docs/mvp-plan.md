# 作業実績アプリ MVP 設計

## 1. 確定した前提

| 項目 | 方針 |
| --- | --- |
| 対象OS | Android 15以降 |
| 圃場 | アプリにテスト用の固定候補を同梱し、アプリ内での追加・編集は行わない |
| 作業内容 | 自由入力。過去に入力した直近5件を候補として表示する |
| 同時作業 | 1件のみ |
| 時刻修正 | 履歴画面から開始・終了日時を修正できる |
| 履歴 | 端末内の過去データを一覧表示する |
| 削除 | 履歴画面から誤った記録を削除できる |
| オフライン | 記録、履歴表示、修正、削除を端末内だけで実行できる |
| 送信先 | さくらインターネットのレンタルサーバー上に置くHTTPS API |
| サーバーDB | MySQL |
| 機種変更 | 未送信データの引き継ぎは行わない |

初期の圃場候補には、テスト用として「第1圃場」「第2圃場」「東圃場」「西圃場」「ハウス1」を使用します。実際の圃場名が決まり次第、同梱データを差し替えます。

## 2. 画面構成

画面は「作業入力」と「履歴」の2つに絞り、下部のタブで切り替えます。

### 作業入力画面

```text
┌──────────────────────────────┐
│ 作業実績                     │
│                              │
│ 圃場                         │
│ [ 第1圃場               ▼ ] │
│                              │
│ 作業内容                     │
│ [ 作業内容を入力           ] │
│ 最近: [草刈り] [水やり]     │
│       [収穫] [消毒] [施肥]  │
│                              │
│ [        作業を開始        ] │
│                              │
│ 作業中: 第1圃場 / 草刈り    │
│ 開始 08:30 / 経過 01:15     │
│ [        作業を終了        ] │
│                              │
│ 未送信 3件                   │
│ [        データ送信        ] │
│ 最終送信 2026/10/01 17:00   │
│                              │
│    [作業入力]      [履歴]    │
└──────────────────────────────┘
```

- 圃場は固定候補から選択し、前回選んだ値を初期表示します。
- 作業内容は自由入力とし、過去の作業実績から使用日時が新しい重複なしの5件を候補表示します。
- 候補をタップすると作業内容へ入力します。候補にない内容もそのまま入力できます。
- 空白だけの作業内容では開始できません。前後の余分な空白は保存時に取り除きます。
- 開始時刻と終了時刻はボタンを押した時刻を自動保存します。
- 作業中は圃場と作業内容を変更できず、別の作業も開始できません。
- 開始は確認なし、終了は確認ダイアログを表示します。
- アプリ終了や端末再起動後も作業中の状態を復元します。
- 未送信件数、送信中、成功、失敗を同じ画面で確認できるようにします。

### 履歴画面

```text
┌──────────────────────────────┐
│ 履歴                         │
│                              │
│ 10/01 第1圃場  草刈り       │
│ 08:30 ～ 09:45   未送信     │
│                    [編集]    │
│                              │
│ 09/30 東圃場    収穫         │
│ 13:00 ～ 15:10   送信済み   │
│                    [編集]    │
│                              │
│    [作業入力]      [履歴]    │
└──────────────────────────────┘
```

- 開始日時の新しい順に表示します。
- 各行に日付、圃場、作業内容、開始・終了時刻、送信状態を表示します。
- 編集画面では開始日時と終了日時を修正できます。
- 終了日時が開始日時以前になる修正は保存できません。
- 削除時は対象内容を示した確認ダイアログを必ず表示します。
- 送信済みデータを修正した場合は未送信へ戻し、次回送信でサーバー側を更新します。
- 送信済みデータを削除した場合は削除情報を未送信として保持し、次回送信でサーバー側も削除します。サーバーで削除が確認されるまでは端末DBから完全削除しません。

## 3. 基本操作

1. 圃場を選択する。
2. 作業内容を入力するか、直近5件から選択する。
3. 「作業を開始」を押すと、開始中の記録を直ちに端末へ保存する。
4. 作業後に「作業を終了」を押し、確認後に終了時刻を保存する。
5. 押し忘れや誤入力があれば、履歴から日時を修正または記録を削除する。
6. インターネットへ接続できる場所で「データ送信」を押す。
7. 成功した変更だけを送信済みにし、失敗分は端末に残して次回再送する。

## 4. Android端末内のデータ

AndroidのSQLiteデータベースをRoom経由で使用します。作業中も含め、すべての変更を先に端末へ保存します。

### `fields`（固定の圃場候補）

| 項目 | 内容 |
| --- | --- |
| `id` | 圃場を識別するID |
| `name` | 圃場名 |
| `display_order` | 表示順 |
| `enabled` | 選択肢に表示するか |

### `work_records`（作業実績）

| 項目 | 内容 |
| --- | --- |
| `id` | 端末で生成するUUID。サーバーでも同じIDを使用する |
| `field_id` | 圃場ID |
| `field_name` | 記録時点の圃場名 |
| `work_content` | 自由入力した作業内容 |
| `started_at` | 開始日時 |
| `ended_at` | 終了日時。作業中は空 |
| `sync_status` | `pending`、`sending`、`sent`、`failed` |
| `created_at` | 作成日時 |
| `updated_at` | 最終更新日時 |
| `sent_at` | 最終送信成功日時。未送信なら空 |
| `deleted_at` | 削除日時。削除されていなければ空 |

直近5件の候補は別のマスターへ登録させず、削除されていない作業実績の `work_content` から重複を除いて取得します。日時はタイムゾーンを含めて正しく送受信できる形式で保持します。

## 5. さくらインターネットとの連携

AndroidからMySQLへ直接接続せず、レンタルサーバー上のHTTPS APIを経由します。これにより、MySQLの接続情報をアプリへ埋め込まずに済みます。

```text
Androidアプリ
    │ HTTPS（JSON）
    ▼
さくらのレンタルサーバー上のAPI
    │ サーバー内だけでDB接続情報を使用
    ▼
MySQL
```

APIには第三者からの不正登録を防ぐ認証情報を付けます。サーバー側では `id` を一意にし、同じ記録を再送した場合は追加ではなく更新することで二重登録を防ぎます。

### データ送信ボタン

1. オフラインの場合は接続が必要であることを表示し、端末の記録は変更しない。
2. 完了済みの新規・修正・削除データをまとめて送る。作業中の記録は送らない。
3. 送信中はボタンを無効にして連打を防ぐ。
4. APIが個別に成功を返した記録だけを `sent` にする。
5. 「3件送信しました」「2件送信、1件未送信」のように結果を表示する。
6. 通信中断やサーバーエラーの場合は `failed` とし、次回の手動送信対象にする。

サーバーのMySQLにも、UUID、圃場、作業内容、開始・終了日時、更新日時、削除日時を保存します。削除はすぐに物理削除せず、`deleted_at` を記録する論理削除にすると、再送や通信中断時にも整合性を保ちやすくなります。

## 6. MVPに含めない機能

- ユーザー登録画面
- GPSによる圃場判定
- 写真添付、作業メモ
- 圃場の追加・編集
- 複数作業の同時記録
- 自動バックグラウンド送信
- 複数端末間のリアルタイム同期
- 未送信データの機種変更時引き継ぎ
- 複雑な集計・グラフ

## 7. 残りの確認事項

実装を開始する前に、次だけ決めれば進められます。

1. 実際に使用する圃場名（試作中はテスト名を使用可能）。
2. さくらのレンタルサーバーでHTTPSが有効になっているドメインまたはサブドメイン。
3. 受信APIの実装に使用するサーバー側言語。未指定ならレンタルサーバーで利用可能な構成を確認して決定する。
4. 送信済みデータも端末の履歴から修正・削除可能としてよいか。本案では可能としています。

## 8. 実装順

1. Android 15以降を対象にプロジェクトを作成する。
2. テスト圃場を入れ、作業入力画面を作成する。
3. Roomで開始・終了、状態復元、直近5件の候補表示を実装する。
4. 履歴一覧、日時修正、削除を実装する。
5. オフライン状態で一連の操作を実機確認する。
6. さくらのレンタルサーバーにHTTPS APIとMySQLテーブルを作る。
7. 新規・修正・削除の手動送信、再送、二重登録防止を実装する。
8. 通信中断を含む送信テストを行う。
